- [x] Find a way to keep the dependency source code out of the repository to reduce noise - the dependencies are resolved by Conan when the addon is built, only the GDAL and PROJ data files and the curl root certificates are still shipped in `deps/`
- [x] Switch to cmake.js - the addon is built from `CMakeLists.txt`, `binding.gyp` and node-gyp have been removed
- [x] Switch from nan to N-API - the addon uses node-addon-api and a single `napi-v8-{platform}-{arch}` binary is published per platform
- [x] Support aborting of GDAL operations (that allow it) through the AbortController (Node.js >= 15) - the long-running operations accept an `abort_signal` option and fail with an `AbortError`; only the operations which support progress callbacks can be interrupted, and only in their asynchronous form
- [x] Support `worker_threads` (almost automatic with N-API) - each thread gets its own Node-API environment and its own object store
- [x] Give every Node-API environment a single context object instead of the current set of `thread_local` variables - `EnvContext` holds the object store, the interned private symbols, the constructor reference of every wrapped class, the pointer hand-off slot of the wrapper factories and the flag which says that the environment is shutting down. It is found through the environment it belongs to, so two loadings of the addon in one process (CJS + ESM) share it, and it outlives the environment, because V8 finalizes the objects which are still alive after the environment cleanup hooks have run
- [x] Replace the hand-rolled `this_` + `owned_` ownership of the wrapped objects with a typed handle whose deleter is fixed at construction - `Handle<T>` (`src/utils/handle.hpp`) keeps the pointer together with the function which frees it, or with no function at all for the objects a parent owns. The classes which own their object (`FieldDefn`, `FeatureDefn`, `Feature`, `SpatialReference`, `Geometry`, `CoordinateTransformation`, `ColorTable`) get the handle from their factory, so there is no flag to forget and the question of who frees what is answered once, where the object is created. `Dataset`, `RasterBand`, `Layer` and `Driver` only borrow their object, because the object store frees those
- [x] Replace the 297 `NODE_ARG_*` uses and the 93 `GDAL_ASYNCABLE_DEFINE` macro definitions with a declarative argument binder and an `AsyncMethod<Impl>` template. One macro expansion per method generates the synchronous *and* the asynchronous variant, and each argument check throws from inside the argument list itself (478 `ThrowAsJavaScriptException`), which is where the "an exception thrown inside a `try` block is swallowed by the `catch (const std::exception &)`" trap lives. The `@param` doc comments stay - yatag parses those, not the macro calls
- [x] Carry the failures in a `GDALError`, a message together with the name and the code of the error it has to become, instead of a bare `const char *`, and build the JS error in a single place (`toJS()`/`throwError()`). The asynchronous worker has one boundary which turns whatever its `Execute()` caught into a JS error, the `AbortError` is no longer built at every call site, and only the `GDALAbortState::interrupted` flag can turn a failure into one, so a genuine GDAL error which happens to arrive after an abort is still reported as itself
- [x] Write every method once, as a body which generates both the synchronous and the asynchronous variant - every method is a body struct behind a single `GDAL_ASYNC_METHOD`/`GDAL_ASYNC_GETTER`/`GDAL_ASYNC_METHOD_STATIC`/`GDAL_SYNC_METHOD`/`GDAL_SYNC_GETTER` expansion, so the two forms of a method are the same code and cannot drift apart. The body takes its arguments from `Args`, checks that `this` is still alive with `unwrapThis()` - which throws in the synchronous form and rejects in the asynchronous one, because a throw from a getter would reach the caller instead of the promise - and ends with `job.run(info, node_gdal::is_async<Async>, cb_arg)` when it has an asynchronous variant. The thirty `NODE_WRAPPED_METHOD*` and `NODE_WRAPPED_GETTER*` macros are gone, `src/gdal_common.hpp` is down to 39 macros, and it keeps only the throwing helpers, the unwrapping checks, the optional argument conversion and the constants
- [x] Make the objects which a parent owns throw when they are written to, instead of silently writing into a clone - `layer.fields.get('x').width = 3`, `feature.defn.geomType = ...` and `layer.srs.setWellKnownGeogCS(...)` used to succeed and change nothing, because the getters hand out copies. The copy is now marked read-only, with a private symbol on the wrapper (`set_read_only()`/`is_read_only()` in `src/gdal_common.hpp`), and every write to one is refused with a `read-only, create a new one to modify it` error: the `FieldDefn` of `Layer.fields` and of a feature definition, the `FeatureDefn` of `Feature.defn` together with its `fields` collection, the `SpatialReference` of `Layer.srs`, of `Geometry.srs` and of the multidim objects, and the `ColorTable` of a band, which already refused to be written to with a message of its own. A copy stays a copy - `clone()` hands out an object which can be modified, and a spatial reference which is already wrapped is handed out as itself, so `geom.srs` is still writable when it is the very object which was assigned to the geometry
- [x] Tell V8 about the memory GDAL holds on our behalf - `AdjustExternalMemory` was called for the geometries and the mem files only, so a process which has opened a hundred datasets looked idle to the garbage collector, which then had no reason to run and collect the wrappers nobody uses. The accounting now belongs to `GDALObject`, as `setExternalMemory()`, and the base destructor gives back whatever a wrapper still holds, so the classes which own memory only have to say how much it is: a `Dataset` reports the blocks of its bands, or the whole raster when it is a MEM dataset, and is re-reported when a band is added to it, a `Feature` reports the size of the geometries it carries, both when it is created and when its geometry is replaced, and the geometries and the mem files report what they already did. The estimate is deliberately on the low side, since a driver keeps its own caches out of reach, and it cannot be asserted from JavaScript - the counter is not visible to `v8.getHeapStatistics()` - so the tests only check that nothing reports so much that the suite is slowed down.
- [x] Keep one source of truth per method: the registration - the same fact was written four times, as the argument binder in C++, as the `@param` comment which yatag reads, as the 11,121 lines of `lib/index.d.ts` and as the `promisifiables` and `argMangle` tables in `lib/gdal.js`, and nothing checked that they agree. `test/api_registration.test.ts` now parses the registration out of `src/` - the `GDALDefineClass<>` descriptor lists and the `GDAL_SetMethod`/`GDAL_SetAsyncableMethod` calls of every `Initialize` - and fails when a registered member has no `@method`/`@name` comment of its class or of one of its ancestors, when a comment survives the member it documents, or when the typings do not declare it. The typings are generated from those comments by `npm run yatag`, so what is documented is typed, and the check found the drift which was there: `SpatialReference.isVectical`, which the registration exposes but nothing documented, `LinearRing.addSubLineString`, a registration which shadowed the inherited `SimpleCurve` method and with it its memory accounting, and the unregistered implementations of `Feature.equals` and `Geometry.create` with their doc comments
- [x] Return the promise from the binding instead of wrapping it in JavaScript - `GDALAsyncableJob::run` already knew at which argument the callback goes, yet `lib/gdal.js` kept a table of 110 `xAsync` to callback index entries in order to promisify the methods. Now an asynchronous method returns the promise itself when the call has no callback: `AsyncMethod<Body>` looks for the callback at the argument the body declared or as the last argument of the call, and a failure which happens before the job starts rejects that promise instead of being thrown at the caller. The table and the `argMangle` map are gone, `Args::optionalCallback` reports the raw index so that the callback is the one argument the binder does not consume, and the 103 asynchronous methods - the ones which take a callback and the getters, which never do - work without a JavaScript wrapper
- [ ] Catch up with the modern Node.js surface - there is no `Symbol.dispose` and no `Symbol.asyncDispose`, so `await using ds = await gdal.openAsync(...)` cannot close a dataset; `package.json` has no `exports` map, so an ESM consumer only gets the CommonJS module through the interop rules; and `engines` still promises Node.js 18, which is out of support
- [ ] Teach the argument binder the flexible shapes of the pixel arguments - `RasterBandPixels.read`/`write`, `RasterBandPixels.readBlock`/`writeBlock` and `MDArray.read` still have their arguments flattened into the positional list which `Args` reads by `mangleRead`, `mangleWrite`, `mangleBlock` and `mangleMDArray` in `lib/gdal.js`, and the type of a `TypedArray` buffer is still passed in through a `_gdal_type` property which JavaScript writes onto it. An `Args` which can declare an options object, or a list of an unspecified length, would remove the last copy of the argument order from JavaScript, together with the `wrapMangled` wrappers
